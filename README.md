# Model Shelf · DSH 模型整理

在聊天输入框旁整理模型：**拖动排序、折叠分组、自定义标签、隐藏与恢复**。

无需离开对话去调整列表，不修改 DSH 本体源码，不改供应商、模型或凭据配置。插件没有模型测试、后台探测或自动切换功能。

## 功能

- **供应商分组**：点击展开、收起，记住折叠状态。
- **拖动排序**：点击「整理」，拖动供应商或组内模型；官方供应商也可以调整展示顺序。
- **自定义标签**：模型右侧的小方框直接输入自己的备注，例如“常用”“代码”“备用”；最多 32 个字符。
- **隐藏与恢复**：整理时隐藏模型，勾选「显示已隐藏」后恢复。
- **搜索**：匹配模型名称、ID、供应商和自定义标签。
- **思考等级**：模型声明了可用等级时，保留独立选择控件。

## 安装

已在 **DeepSeek Harness Desktop 0.2.0-rc.2 / Windows** 安装并使用验证。其他版本和其他客户端暂未验证。

### 桌面端：粘贴地址安装

打开 **设置 → 插件 → 添加插件**，在「包名或地址」粘贴：

```text
https://github.com/Sky-lll27/dsh-model-shelf/releases/download/v0.1.1/dsh-model-shelf-0.1.1.tgz
```

点击安装，完成后退出并重新打开 DSH。然后点击聊天框旁的模型名称；菜单底部会显示 `初版 0.1.1`。

也可以填写仓库地址安装：

```text
https://github.com/Sky-lll27/dsh-model-shelf
```

仓库已包含运行文件，没有 prepare 安装脚本，不需要本地编译。

### CLI

适用于由 CLI 管理的 web profile：

```sh
dsh plugin --profile web add https://github.com/Sky-lll27/dsh-model-shelf/releases/download/v0.1.1/dsh-model-shelf-0.1.1.tgz
```

安装后重启 DSH。桌面 profile 请优先使用桌面客户端的插件管理界面。

## 使用

1. 点聊天框旁的模型名称。
2. 点供应商名称展开模型；点「全部展开 / 全部收起」统一整理视图。
3. 点「整理」后，从左侧拖动手柄调整顺序，点「完成」退出整理。
4. 在模型右侧方框输入自定义标签，自动保存。
5. 整理时点「隐藏」移出本插件菜单；勾选「显示已隐藏」后点「恢复」。

## 数据与边界

- 排序、折叠、标签和隐藏状态保存在当前浏览器的 localStorage，键为 `dsh-model-shelf.preferences.v1`。不上传数据，不写入提示词。
- 偏好跟随同一浏览器的同一来源（协议、主机、端口），不同设备、浏览器或端口之间不自动同步。浏览器拒绝存储时显示提示，本次页面内仍可操作。
- 模型按“供应商 ID + 模型 ID”区分，同名模型可以分别整理。新增模型追加到当前组，不改原始模型目录。
- 隐藏只影响本插件菜单，不禁止后台调用，不修改当前已选模型。原生 `/model` 菜单不采用本插件的展示偏好。
- 选择模型走 DSH 自己的模型选择接口；只有用户点击选择或调整思考等级时才提交切换，不发送模型提示词。
- **同一个 profile 建议只启用一个替代模型选择器插件**，避免占用相同的聊天模型选择入口。
- 当前为初版；尚未专门优化移动端，也未验证其他 DSH 版本。

## 更新与卸载

如当前 DSH 不支持直接更新，在 **设置 → 插件** 卸载本插件，再添加新版并重启。相同浏览器来源下，已有展示偏好会保留。

卸载后恢复原生模型选择器。需要同时清除本插件偏好时，在浏览器开发者工具执行：

```js
localStorage.removeItem('dsh-model-shelf.preferences.v1')
```

## 开发与验证

运行代码在 `lib/client.js`，通过 DSH 的客户端模块加载器和官方模型选择扩展接口挂载。宿主入口 `lib/index.js` 为空。无需构建，无运行时 npm 依赖（React 和 ReactDOM 由 DSH 宿主提供）。

```sh
npm test
npm run pack:release
```

测试检查实际插件的加载/注册、目录接口、排序/隐藏/标签行为、切换失败处理和包内容。打包脚本生成仅包含 6 个发布文件的 `.tgz`，不包含测试、开发环境或用户配置。

该版本开发时做过实际浏览器交互验证：双向拖动、保存与刷新、隐藏恢复、标签编辑、切换成功/失败；随后在用户桌面版安装并由用户确认可用。自动化测试不访问真实模型、不消耗模型额度。
